# Independent Embedding comparison page

Entry: Compare → Embedding sayfasını aç. It is a dedicated navigation destination, separate from RAG; no comparison link remains in the RAG page. The bottom bar retains five tabs. Text-to-text comparison remains available, with optional common LLM answer generation. The initial mode is text-to-image search, where LLM answers are not generated.

The installed LiteRT-LM 0.18.0 API was verified locally: `InputData.Image(byte[])`, `EmbeddingEngineConfig.visionBackend`, `visionTokensPerImage`, and `EmbeddingEngine.computeEmbedding` are present. Image experiments initialize the 740M bundle with CPU text and vision backends (four threads) and 70 vision tokens. They embed encoded image bytes directly. The 270M side embeds manually supplied descriptions using its normal document text prefix. Both use normalized embeddings at the selected output dimension and exact cosine ranking against the same labelled images.

Select 2–200 images, enter a description for each, and provide 1–100 queries in the form `question | correct image numbers |`. Multiple relevant images can be labelled with comma-separated numbers. Image thumbnails establish the association between photo and numeric label. The app computes Recall@1, Recall@5, full-ranking MRR, binary nDCG@5, initialization/indexing duration, per-item embedding times, indexing throughput, query-plus-search duration and sampled whole-application PSS. JSON export includes descriptions, image URIs, ground-truth labels, complete rankings, raw times and method limitations.

Manual descriptions are an explicit baseline: caption-generation cost is not measured, and this is not a full automatic captioning-system benchmark. Image reading is included in the 740M indexing measurement. PSS is sampled after embeddings and is not an isolated model memory measurement or guaranteed instantaneous peak. This experiment uses one pass per side, not repeated alternating rounds. No automatic accuracy claim is made without labelled data. A 100-photo/50-query real benchmark dataset is not bundled; users supply it. Image-to-image, audio retrieval and energy measurements are not implemented by this change.

Validation: Kotlin compilation and unit tests; `ImageEmbeddingSmokeTest` uses two synthetic solid-colour PNGs to exercise real 270M caption embedding and real 740M image embedding on Android. That fixture is an API smoke test, not a photo-search accuracy benchmark.
